01 · What it is

A colleague you can hand real work to.

Most AI tools answer questions. Claude Code takes on the job. Give it a folder and a goal, and it reads what is there, makes a plan, writes and edits the files, runs the tests, fixes what breaks, and comes back with a summary. The kind of task you would hand to a capable colleague, done in a conversation, with you deciding what ships.

A chatbot

Hands the work back to you.

It answers, you paste the answer somewhere, you fix what did not fit, you come back with the next question. Every step still runs through your hands.

Claude Code

Carries the work end to end.

It reads the project, plans, writes the files, runs the tests, fixes the failures, and reports. Jobs with twenty steps, with a question when something is unclear and a permission prompt before anything risky.

You

Decide what ships.

You set the goal, answer its questions, approve anything that touches the outside world, and read what changed. Judgment stays with you.

Our view, after building Edge's own internal tools this way: the unlock is delegation. Once you can describe an outcome clearly and check the result, you can hand over work you would never have attempted yourself, and most people who have never written code already have those two skills. Syntax was the wall. The wall is gone; the judgment still counts.

03 · Set up

Ten minutes to a working setup.

Two doors into the same tool. The Desktop app runs Claude Code with buttons, panes, and a visual diff for every change; the terminal is where it started and runs anywhere. Pick one, and switch later if you like. Everything else on this page applies to both.

Also: VS Code and JetBrainsInline diffs inside the editor you already use.
Also: claude.ai/codeCloud sessions from a browser or your phone, on a copy of your repository.

  1. Install the app and sign in

    Download Claude for macOS or Windows at claude.com/download, open it, and sign in with your Claude account. Claude Code needs a paid plan: Pro, Max, Team, or Enterprise. On Windows, install Git for Windows first, then restart the app.

  2. Open the Code tab

    The app has three tabs: Chat, Cowork, and Code. Code is where Claude Code lives. Every conversation there is a session with its own project folder and its own changes, and you can run several side by side.

  3. Point it at a folder

    In the prompt area, choose Local as the environment and select your project folder. No project yet? Make an empty folder called village-notes and pick that. Claude only sees the folder you choose, which is exactly what you want.

  4. Set the mode

    The mode selector sits next to the send button. Start in Manual: Claude asks before it edits a file or runs a command, and shows you the diff. Switch to Plan for anything big, then back to execute. Some accounts also show Auto, where a second model reviews actions so you approve less often.

  5. Type your first ask, then give it a memory

    Plain English, then Enter. Drag in a screenshot, or type @ to mention a file. When Claude changes something, a +12 -1 indicator appears; click it to open the diff and comment on any line. After the first task, type /init in the prompt box and Claude drafts a CLAUDE.md for the folder. Section 05 shows what to put in it.

  1. Open a terminal

    Mac: press ⌘ Space, type Terminal, press Enter. Windows: open PowerShell from the Start menu. A dark window with a blinking cursor is the whole thing.

  2. Install Claude Code

    Paste one line and press Enter. It installs itself and keeps itself updated.

    curl -fsSL https://claude.ai/install.sh | bash
    irm https://claude.ai/install.ps1 | iex
    brew install --cask claude-code

    Check it worked: type claude --version. A version number means you are done.

  3. Go to a project folder

    Claude Code works inside whatever folder you start it from. Type cd, a space, then drag the folder from Finder or Explorer onto the terminal window and press Enter. No folder yet? Make one:

    mkdir village-notes && cd village-notes

  4. Start it and log in

    claude

    The first run opens your browser to log in. Claude Pro, Max, Team, and Enterprise all include Claude Code; a Claude Console account with API credits works too. The free plan does not include it.

  5. Give it a memory

    /init

    Claude reads the folder and drafts a CLAUDE.md, the file where it keeps notes about your project. It is a plain text file you can edit any time. Section 05 shows what to put in it.

Never opened a terminal? Two ideas and you are fine.

Idea one: the terminal is a text box that talks to your computer. You type a command, press Enter, and it does the thing or prints a message. Looking around cannot break anything.

  • pwd prints where you are (the folder the terminal is "standing in").
  • ls lists what is in that folder.
  • cd Documents steps into a folder; cd .. steps back out.

Idea two: Claude Code only sees the folder you start it in. That is a feature. Keep one folder per project, start claude inside it, and it works on that project alone.

Stuck on any command, in Claude Code or out of it? Ask Claude what it does. Explaining is one of the things it is best at.

What it costs. Subscriptions include Claude Code within each plan's usage limits, and /usage shows how much of the window you have used. Console accounts pay per token and see a running dollar figure in the same place. Long sessions cost more than short ones, which is one reason for the /clear habit in section 06.

05 · Teach it your world

Claude knows everything about software and nothing about your project.

CLAUDE.md fixes that. It is a plain text file in your folder that Claude reads at the start of every session: what the project is, how you like to work, what to never do. Fill in the blanks, copy the file, and watch every answer get better.

Example values. Replace them with your own; the file on the right updates as you type.

06 · Habits

      
Eight habits that separate frustrating from fluent.

      
Each card has a vague prompt on the back and a better one under it. Tap or hover to flip.

    

    

      

        
Habit
Look before leaping.
Ask it to explore and explain first. Changes come after understanding.
flip for the prompt

        
Instead of"Fix the login bug."
Try"Read how login works and tell me the three most likely causes of the redirect bug before changing anything."

      

      

        
Habit
Give it a way to check.
A test, a screenshot, a URL, an expected output. It will iterate until it passes.
flip for the prompt

        
Instead of"Make the chart look right."
Try"The bars overlap the labels at 390px wide. Fix it and show me a screenshot at that width."

      

      

        
Habit
Describe the outcome.
Say what done looks like, and name files and constraints. Leave the keystrokes to it.
flip for the prompt

        
Instead of"Open the CSS file and change line 40 to blue."
Try"Buttons should use our brand blue, #0E5A82, everywhere, including hover and focus states."

      

      

        
Habit
Plan mode for big changes.
Anything touching more than a few files: switch to plan mode, approve the plan, then build. Shift+Tab in the terminal; the mode selector in Desktop.
flip for the prompt

        
Instead of"Rewrite the payment flow."
Try"/plan Propose how you would restructure the payment flow. Do not change anything yet."

      

      

        
Habit
Interrupt early.
The moment it heads the wrong way, stop it and say what you wanted. Waiting for the wrong thing to finish is the expensive move.
flip for the prompt

        
Instead ofWatching it rebuild the layout you liked.
TryStop it (Esc, or the stop button), then: "Keep the existing layout; only change the colors."

      

      

        
Habit
/clear between tasks.
Context is a whiteboard. A full one makes it worse at everything. Two failed corrections in a row means clear and rephrase.
flip for the prompt

        
Instead ofOne endless session for the whole day.
Try"/clear" then a fresh, specific ask. "/compact" when you need to keep the thread and lose the noise.

      

      

        
Habit
Commit small, often.
Git is the undo button. Ask for a commit after each working step and you can always go back.
flip for the prompt

        
Instead ofOne giant change at the end of the day.
Try"Commit what we have with a clear message" every time something works.

      

      

        
Habit
Read the diff.
You own what ships. When anything is unclear, ask for the explanation, in plain language.
flip for the prompt

        
Instead ofAccepting every edit because the tests passed.
Try"Explain what you changed and why, in plain language, and what you would watch for."

      

    


    

      

        
Three rules for your real machine

        
Fast is fine. Reckless is not.

        
Claude Code is careful by default. These rules keep it that way once you start moving quickly.

      

      
    
        
  1. 1
    Keep the permission prompts. --dangerously-skip-permissions belongs in a throwaway container, never on the laptop with your life on it. Auto mode is the fast option that still has a reviewer in the loop.
    2. 
        
  2. 2
    Keep secrets out of prompts and commits. Put keys in a .env file, add it to .gitignore, and say so in CLAUDE.md. Claude can use a key without you ever pasting it into chat.
    3. 
        
  3. 3
    Outbound actions need your explicit yes. Sending, paying, deploying, deleting. Ask it to draft and stop; you press the button. Draft-only is a habit worth building on day one.

07 · Three weeks in Goa

      
One workshop a week, and the days in between are the point.

      
Each week's workshop opens a track. Build clinics between them turn what you saw into something you made. Bring a project; the format works best when the thing you build is yours.

    

    

      

        

          
Week 1Oct 11 to 17

          
Beginner

          
From an idea to a working tool.

          

            
Arrive with
An idea, or a folder of notes. Zero terminal experience is fine.

            
Leave with
Claude Code installed, a CLAUDE.md, and one tool you built and can show someone.

            
You will learn
The loop, permission prompts, plain-language iteration, /init, /clear, and enough git to undo.

          

        

        

          
Week 2Oct 18 to 24

          
Intermediate

          
Bring a real project.

          

            
Arrive with
A codebase, or a workflow you still run by hand.

            
Leave with
A feature shipped with tests, a Skill your team can reuse, and one connected tool.

            
You will learn
Skills in .claude/skills/, MCP servers for Notion, Drive, and databases, hooks that run after every edit, and claude -p inside scripts.

          

        

        

          
Week 3Oct 25 to Nov 1

          
Advanced

          
Agents that run without you. Then the hackathon.

          

            
Arrive with
Something you want to keep running after you leave the room.

            
Leave with
An agent with checks around it, scheduled runs, a pull-request workflow, and a demo for the showcase.

            
You will learn
Subagents, worktrees for parallel sessions, Claude Code on the web and in CI, Routines that run on a schedule, and the Agent SDK.

          

        

      

    

    

      
WorkshopsOne per week, roughly ninety minutes, then a build session in the same room.

      
Build clinicsTwice a week, open to everyone. Bring the thing that broke.

      
Hackathon and showcaseWeek 3. Teams, a deadline, and an audience. Finished beats perfect.
